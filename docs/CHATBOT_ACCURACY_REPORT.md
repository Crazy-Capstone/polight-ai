# 챗봇 정확도 측정 및 개선 리포트

여행자보험 AI 챗봇을 사용자 테스트 시나리오로 측정하고, 프롬프트를 개선해 정확도를 끌어올린 과정입니다.

**최종 결과: 챗봇 답변 정확도 0.804 → 0.964 (+16%p)**

---

## 0. 무엇을 측정했나 (측정 대상 정의)

**측정 대상: RAG 챗봇 파이프라인 전체의 "답변 정확도"** — 사용자 질문에 대해 챗봇이 내놓은 최종 답변이, 약관·증권에 근거한 정답과 얼마나 일치하는가.

이것은 **응답 LLM 단독 성능이 아닙니다.** 답변은 아래 여러 단계를 거쳐 나오고, 정확도는 그 전 과정의 합작 결과입니다.

```
질문 → 질의 재작성(LLM) → 임베딩(Upstage) → 약관 검색(pgvector+BM25)
     → 근거 재정렬(MMR) → 증권 가입정보 결합 → 답변 생성(LLM) → 최종 답변  ← 측정 지점
```

따라서 이 수치는 다음을 **모두 포함한** 정확도입니다.
- 검색이 올바른 약관 조항을 찾았는가 (Retrieval)
- 증권 가입정보(담보·한도·자기부담)가 반영됐는가
- LLM이 근거를 정확히 종합해 답했는가 (Generation)
- 면책·조건·청구기한 등을 빠뜨리지 않았는가

**측정 대상이 아닌 것**
- 응답 모델(GPT-4.1) 자체의 벤치마크 성능
- 검색 단독 성능(Recall@k) — 이번 지표는 최종 답변 기준이며, 검색은 그 안에 포함됨
- 답변의 문체·길이·가독성 (정확도만 봄)

**고정한 조건** (이 조건이 바뀌면 수치도 달라짐)
- 답변 모델: OpenAI GPT-4.1
- 임베딩: Upstage (upstage-1536)
- 대상 약관: 메리츠화재 해외여행보험(플랫폼) 1종
- 증권: 시연용 메리츠 여행자보험 (담보 20종, coverages 주입)
- 개선한 것은 **프롬프트와 평가셋**이며, 모델·검색 엔진은 동일하게 유지

즉 이 리포트의 개선폭(+16%p)은 **모델을 바꾼 결과가 아니라, 같은 모델·같은 검색에서 프롬프트를 개선해 얻은 답변 정확도 향상**입니다.

## 1. 측정 방법 설계

### 평가셋

실제 사용자 테스트에 쓸 두 시나리오를 그대로 챗봇 질문으로 변환해 평가셋으로 삼았습니다.

- **시나리오 A** — 바르셀로나 소매치기 (현금·노트북·이어폰 도난)
- **시나리오 B** — 방콕 항공 지연 + 수하물 파손 (캐리어·카메라렌즈 파손, 식사비)
- **총 16문항** (A 7문항 + B 9문항)

### 문항 유형과 정답지(gold)

각 문항의 정답을 **약관 청크로 직접 검증**해 고정했습니다. 채점자가 누구든 같은 결과가 나오도록 정답을 못박은 것이 신뢰도의 핵심입니다.

| 유형 | 문항 수 | 예 |
|---|---|---|
| 단일선택 | 6 | 청구기한(3년), PIR 발급시점, 항공사 배상관계 |
| 다중선택 | 4 | 현지에서 해야 할 일, 필요 서류 |
| 보상여부 (항목별 O/X) | 2 | 현금=X, 노트북=O, 정신적피해=X |
| 수치 (예상 보상금액) | 2 | 39만원, 45만원 |
| 서술 (금액 산출근거) | 2 | 품목별 한도·자기부담금 계산 논리 |

**검증한 핵심 정답 예시**
- 현금·신용카드 = 통화 면책이라 보상 안 됨
- 노트북·이어폰·캐리어·렌즈 = 개당 20만원 한도, 자기부담금 사고당 1만원 공제
- 청구기한 = 소멸시효 3년 (도난 "30일 내 발견"은 청구기한이 아니라 보상 성립 조건)
- 항공지연 = 특약 가입 + 4시간 이상 지연 요건
- 정신적 피해 = 보상 항목 없음

### 측정 조건

- 증권 가입정보(coverages)를 주입한 상태에서 측정 (백엔드가 전송하는 것과 동일)
- 답변 생성: OpenAI GPT-4.1
- 반복(repeat): LLM 답변 비결정성을 흡수하기 위해 최종 측정은 문항당 2회 평균

## 2. 채점 방식 — 규칙 기반에서 LLM 채점으로 전환

### 처음엔 규칙 기반 키워드 매칭

정답 키워드가 답변에 있는지 문자열로 대조했습니다. 객관식·수치엔 좋지만, 자연어 답변의 **표현 차이**를 못 잡았습니다.

**문제 사례**
- 정답 "공항 나서기 전" ↔ 답변 "공항 도착 후 바로" → 같은 개념인데 0점
- 정답 "차액만/대위" ↔ 답변 "항공사 배상액을 제외한 나머지" → 정답인데 0점

키워드를 답변에 맞춰 늘릴수록 **오버피팅**(답변 보고 채점 기준 맞추기)이 됐습니다.

### LLM 채점으로 전환

정답(gold)을 주고 LLM이 "정답 개념을 맞게 답했는지"를 0~1로 판정하게 했습니다.

- 표현이 달라도 정답 개념이면 인정 → 표현 차이 흡수
- 정답이 고정돼 있어 채점자 재량이 제한됨 (후하게 못 줌)
- 부분 정답은 부분 점수
- 정답을 빠뜨리거나 반대로 답하면 감점 (진짜 오답은 계속 걸림)

**효과**: 규칙 채점 0.755 → LLM 채점 0.804. 규칙이 놓치던 정답들(A4·B3·B4 등)이 제대로 잡히면서 진짜 기준선이 드러났고, 동시에 **진짜 약점(A7 오답, B8 맥락 문제)**도 드러났습니다.

## 3. 무엇을 바꿨나 — 개선 항목

LLM 채점 Before(0.804)에서 드러난 약점을 프롬프트로 개선했습니다.

### (1) 절차·상식 안내 허용
**문제**: 기존 프롬프트 규칙("약관 근거만 사용, 근거 없으면 추측 금지")이 "지금 뭘 해야 하나", "서류 언제 발급받나" 같은 절차 답변을 통째로 억제 → 경찰신고만 말하고 카드정지·기록 등을 누락.
**개선**: "보상 판단은 약관 근거로만, 단 사고 대응·청구 절차는 일반 여행자보험 상식으로 빠짐없이 안내(약관 근거 아님을 표시)".
**대상**: A1(현지 해야할일), A2·B2(서류), B1(공항 절차)

### (2) 청구기한 혼동 방지
**문제**: 챗봇이 "도난은 30일 내 발견"(보상 성립 조건)을 청구기한으로 착각해 "30일 이내 청구"라고 오답.
**개선**: "청구권 소멸시효(사고일부터 3년)를 먼저 답하고, 특약별 별도 기한(항공지연 30일)이 있으면 함께 밝힐 것. 사고 조건과 청구기한을 혼동하지 말 것".
**대상**: A7 (0.30 → 1.00, 오답 교정)

### (3) 금액은 구체적으로 계산
**문제**: 산출근거를 물으면 일반론만 설명하고 구체 숫자를 안 씀.
**개선**: "금액·산출근거 질문엔 [가입 정보]의 한도·자기부담금과 약관의 개당 한도를 품목별로 적용해 숫자로 계산(예: 노트북 150만→20만 한도, 이어폰 25만→20만, 합 40만−자기부담 1만=39만)".
**대상**: A5·A6·B7·B8

### (4) 나열된 항목 빠뜨리지 않기
**문제**: 질문에 여러 항목(현금·노트북·카드)이 있으면 일부를 누락.
**개선**: "나열된 항목을 하나도 빠뜨리지 말 것".
**대상**: A4(보상여부)

### (5) 특약 가입 전제 명시
**문제**: 항공지연 보상조건에서 지연 시간만 말하고 "특약 가입 필요"를 누락.
**개선**: "보상 조건 질문엔 '① 해당 특약 가입 + ② 약관 지급 요건'을 둘 다 밝힐 것".
**대상**: B6 (지연조건)

### (6) 측정 결함 수정 — 산출근거 질문 자립화
**문제**: "그 금액은 어떻게 계산?"을 앞 문항 맥락 없이 단독으로 던지니 챗봇이 뭘 묻는지 몰라 엉뚱하게(의료비로) 답함. **이는 챗봇이 아니라 측정 설계의 결함**.
**개선**: 평가셋의 산출근거 질문을 자립형으로 변경("도난한 현금30만·노트북150만·이어폰25만에 대해 항목별 계산 알려줘").
**대상**: B8 (0.00 → 0.85)

## 5. 요약

1. **측정 신뢰도를 먼저 확보** — 정답을 약관으로 검증해 고정하고, 규칙 채점의 표현차 한계를 LLM 채점으로 극복. 채점을 답변에 맞추는 오버피팅을 피함.
2. **진짜 약점만 개선** — LLM 채점으로 드러난 실제 오답(청구기한 혼동)·누락(절차·항목)·측정 결함(맥락 없는 질문)을 프롬프트와 평가셋으로 각각 해결.
3. **수치로 증명** — 같은 평가셋·같은 채점으로 Before/After를 비교해 0.804 → 0.964 개선을 확인.

측정 도구(`scripts/eval_scenarios.py`)와 정답지(`data/eval/scenario_gold.json`)는 그대로 남아, 이후 약관 추가·프롬프트 수정 시 회귀 측정에 재사용할 수 있습니다.
